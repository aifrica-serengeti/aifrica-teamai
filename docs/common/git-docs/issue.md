# **Commit Message 작성 규칙**

## **기본 원칙**

- **제목은 한 줄로 변경 내용을 간결하게 작성**
- **현재형 문장 사용**
- **마침표 사용하지 않음**
- **한 commit은 하나의 변경만 포함**
- 문장을 서술형이 아니라 명사형 문장으로 작성
- **30~50자 이내**
- 너무 길면 body에 추가

## **1. 기본 구조**

```
제목

* 본문 (필요한 경우 작성)
```

예시

```
모델 배포 API 추가

* 모델을 서빙 환경에 배포할 수 있는 API를 추가
* GPU 자원 검증 로직을 포함하여 quota 초과 시 배포가 실패하도록 처리
```

---

## **2. 제목(Subject) 작성 규칙**

- **한 줄로 변경 내용을 간결하게 작성**
- **동사 + 대상 형태로 작성**
- **현재형 문장 사용**
- **마침표 사용하지 않음**
- **30~50자 이내 권장**

### **권장 패턴**

```
[동사] + [대상] + [설명]
```

### **예시**

```
모델 서빙 배포 API 추가
GPU 사용량 모니터링 기능 추가
vLLM 배포 시 메모리 검증 로직 추가
AAS Tool 실행 오류 수정
Serving Manager 구조 리팩토링
Helm 배포 설정 업데이트
설치 가이드 문서 업데이트
```

---

## **3. Body 작성 규칙 (필요한 경우)**

다음과 같은 경우 **본문을 작성하는 것을 권장**

- 변경 이유 설명이 필요한 경우
- 변경 범위가 큰 경우
- 동작 방식이 변경된 경우
- 다른 개발자가 이해하기 어려운 로직 변경

### **작성 방법**

- 제목과 **한 줄 공백 후 작성**
- **변경 이유 또는 상세 내용 설명**
- 필요 시 **여러 줄 작성 가능**

---

### **예시 1**

```
GPU 자원 검증 로직 추가

* 모델 배포 시 GPU quota를 초과하는 경우 배포가 실패하도록 검증 로직을 추가
* 기존에는 자원 검증 없이 배포가 진행되는 문제가 있었음
```
