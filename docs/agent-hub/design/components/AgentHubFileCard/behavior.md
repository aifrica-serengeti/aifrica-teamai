# AgentHubFileCard — 동작과 상태 소유권

Figma에서 확인한 것은 세 상태의 표시이며 실제 pointer·keyboard 이벤트/API·메뉴 항목은 구현 증거가 아닙니다.
다음 활성화·선택 분리는 공용 의미 계약을 적용하기 위한 제품 구현 의무입니다.

- 파일 ID·이름·유형·미리보기 URL·권한·조회·정렬·상대시간·선택 ID 집합은 제품 owner가 공급합니다.
- 카드의 주 실행은 제품이 정한 파일 열기/상세 보기 한 가지입니다. 표시 전용 카드는 억지로 버튼이 되지 않습니다.
- checkbox는 선택만 바꾸고 더보기는 해당 파일 메뉴만 엽니다. 두 조작이 카드 활성화를 함께 실행하면 안 됩니다.
- 선택은 외부 값으로 제어하고 `hovered` 같은 디자인 state를 요청 상태 enum에 저장하지 않습니다.
- 사용자가 파일을 선택한 뒤에도 선택 링·선택 checkbox는 포인터가 벗어난다고 없어지지 않습니다.
- 메뉴를 닫았을 때 호출한 조작으로 focus를 돌려줍니다. 삭제·권한·메뉴 내용·실패 처리는 메뉴/제품 owner의 계약입니다.

card 전체를 button으로 만들고 그 안에 더보기 button/checkbox를 중첩하지 않습니다.
복수 조작이 있는 표면은 비대화형 wrapper와 주 실행 host, checkbox, 더보기의 형제 관계로 구성합니다.
메뉴/checkbox 이벤트는 주 실행 host에 겹치지 않아야 하며 단순 `stopPropagation`만으로 잘못된 DOM을 정당화하지 않습니다.

hover에서만 보이는 조작은 키보드 focus가 들어왔을 때도 탐색할 수 있어야 합니다. 터치에서 hover가 불가능하면
항상 보이게 하거나 동등한 메뉴·선택 진입 경로를 제공합니다. 이는 Figma의 추가 variant를 발견했다는 뜻이 아닙니다.

사진형의 제목은 시각 레이어에 없어도 실제 접근 가능한 파일 식별 정보는 제품에서 제공해야 합니다.
hover dim/더보기 때문에 사진을 다시 요청하거나 selected 전환 때 이미지가 깜빡이게 remount하지 않습니다.

미리보기 실패·지원하지 않는 확장자·긴 파일명·여러 파일 선택·파일 삭제 후 선택 해제는 제품 로직입니다.
이번 문서는 진짜 저장소·업로드·다운로드·백엔드 API 구현을 추가하지 않습니다.
