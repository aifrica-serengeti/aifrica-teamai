# GitHub 작업 템플릿

[← 작업 흐름](./README.md)

repository의 Issue Form이나 PR template이 있으면 그것을 우선한다. 아래 템플릿은 필수 정보가
빠지지 않게 만드는 독립형 기본안이다.

## Issue 템플릿

```md
## 개발 목표

이 작업이 병합된 뒤 사용자 또는 개발자가 얻는 결과를 적는다.

## 배경 / 근거

현재 문제, 재현 조건, 요구사항·디자인·API 근거를 적는다.

## 작업

- 변경할 책임과 산출물
- 보강할 상태·오류 처리·테스트
- 문서 또는 디자인 계약 동기화 범위

## 완료 조건

- [ ] 사용자 동작과 시각 결과를 검증할 수 있다.
- [ ] loading·empty·error·disabled 등 관련 상태가 유지된다.
- [ ] 필요한 keyboard·focus·ARIA 동작을 확인했다.
- [ ] package.json과 CI에 정의된 필수 검증이 통과한다.

## 제외

- 이번 Issue에서 변경하지 않을 API·디자인·리팩터링 범위

## 선행 조건

- 선행 Issue, 정책, 디자인, API 결정 또는 `없음`
```

## Pull Request 템플릿

회사 공통 `pr-agent.md` 형식이다. 소비 저장소 template이 추가 항목을 요구하면 그 안에서 이 필수 정보를 유지한다.

```md
## 변경 내용

Issue의 목표와 변경 후 사용자에게 생기는 결과를 요약한다.

## 주요 변경 사항

- 핵심 설계와 상태 소유자, 재사용한 컴포넌트
- 리뷰 순서에 맞춘 변경과 중요한 선택 이유
- 알려진 위험, 실행하지 못한 검증, 후속 범위

## 관련 이슈

Closes #<issue-number>

## 테스트

- 실제 실행한 명령과 관찰한 결과
- 필요한 route·viewport·theme·keyboard·failure 상태 확인
- 미실행 항목과 이유
```

실행하지 않은 검증은 체크하지 않는다. “전체 통과” 대신 실제 명령과 결과를 남긴다.

## 리뷰 답변 템플릿

### 수정 필요

```md
### 리뷰 반영: <finding link>

- 판정: `수정 필요`
- 확인: 지적이 재현되는 조건과 영향
- 변경: 수정한 코드와 추가한 회귀 테스트
- 커밋: `<commit-sha>`
- 검증: 실행한 명령과 결과
```

### 설명 필요

```md
### 리뷰 반영: <finding link>

- 판정: `설명 필요`
- 확인: 혼동이 생긴 코드·계약 맥락
- 변경: 코드·이름·주석·PR 설명 중 보완한 내용
- 커밋: `<commit-sha 또는 변경 없음>`
- 검증: 확인한 테스트·타입·계약
```

### 오탐

```md
### 리뷰 반영: <finding link>

- 판정: `오탐`
- 확인: 실패 조건이 성립하지 않는 구체적인 호출·타입·상태 계약
- 변경: 없음
- 근거: 관련 코드·테스트·문서 링크
```

### 보류

```md
### 리뷰 반영: <finding link>

- 판정: `보류`
- 확인: 유효하지만 현재 Issue의 완료 조건을 차단하지 않는 이유
- 변경: 없음
- 후속 작업: #<follow-up-issue>
- 현재 안전성: 이번 PR을 병합해도 되는 기술적 근거
```

## 후속 Issue 템플릿

리뷰 중 발견된 범위 밖 작업을 단순 TODO로 남기지 않는다.

```md
## 개발 목표

후속 작업이 해결해야 하는 결과.

## 발견 근거

- 원 PR: #<pr-number>
- 리뷰 지적: <finding link>
- 현재 PR에서 처리하지 않은 이유

## 작업

- 필요한 구현과 테스트

## 완료 조건

- [ ] 재현 조건이 해결된다.
- [ ] 회귀 테스트가 통과한다.

## 제외

- 원 PR에서 이미 해결된 범위
```
